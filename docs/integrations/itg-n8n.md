## Серверный контракт и секреты

- n8n/сервер сайта вызывает `POST <StudioFlow HTTPS URL>/api/v1/integrations/leads` с `Authorization: Bearer <ограниченный токен StudioFlow>`, `Content-Type: application/json`, `X-StudioFlow-Request: 1`.
- Токен создаётся OWNER/ADMIN для отдельной тестовой студии/воронки, хранится только сервером/n8n Credentials. Никогда не добавлять его в браузерный JS, URL, экспорт workflow или Git.
- API-ключ n8n нужен для управления workflow, а не вместо токена StudioFlow и не вместо проверки подписи webhook. Передать ключ через приватное хранилище/окружение, не чат. Не добавлять рабочий ключ в `.env.example`.
- UUID создаётся и сохраняется для одной принятой заявки на серверной стороне. При сетевой ошибке повторять тот же UUID и нормализованное тело: новый UUID при каждом повторе создаст дубли. Для надёжности нужна долговечная очередь/квитанция на стороне источника, а не только браузерный UUID.
- Действующий контракт: [входящие заявки](../aspro/scenarios/incoming-leads.md). Он создаёт компанию/контакт/сделку транзакционно, не выполняет автоматическое слияние.
- Обратные события StudioFlow → n8n — отдельное подключение: три поддерживаемых события, HMAC raw body, проверка времени и долговечная дедупликация `event_id`. [Контракт исходящих событий](../aspro/scenarios/outgoing-webhooks.md). Worker остаётся выключен до отдельного согласования.

### Приватная настройка на текущей Windows-машине

Если ключ уже отправлялся в чат, сначала отозвать его в n8n. Новый ключ не присылать повторно. Для временного локального доступа оператор может в своём PowerShell выполнить:

```powershell
Read-Host 'Новый API-ключ n8n' -AsSecureString |
  ConvertFrom-SecureString |
  Set-Content -LiteralPath "$env:LOCALAPPDATA\Temp\opencode\n8n-api-key.dpapi"
```

Команда требует интерактивного ввода на стороне оператора, не запускается агентом автоматически. Ввод скрыт, в истории команды нет значения ключа; Windows DPAPI шифрует файл для текущего пользователя/машины. Файл находится вне репозитория, его содержимое нельзя публиковать/выводить в чат. Это временное локальное хранение, не конфигурация production n8n/StudioFlow. После настройки достаточно сообщить о готовности, без секрета. Проверка доступа должна быть read-only, с заголовком `X-N8N-API-KEY`, без redirect и без вывода заголовков/ключа; при ошибке не публиковать тело ответа, которое может содержать чувствительные данные.

## Приёмка до активации

1. Подключить MCP сайта и приватный API-доступ n8n; сначала читать настройки, без публикации/активации.
2. Согласовать тестовый контур, публичный адрес StudioFlow, студию/воронку, карту полей, хранение согласий и политику персональных данных в execution logs n8n.
3. Подготовить неактивный workflow/адаптер без встроенных секретов, не менять действующие формы.
4. Только на разрешённом тестовом получателе: одна синтетическая заявка → компания/контакт/сделка; повтор → те же ID; изменённое тело с тем же UUID → 409; ошибка/timeout → сохранённая заявка для повтора; отозванный токен → отказ; чтение чужой CRM невозможно.
5. Для обратных событий проверить HMAC, просроченную/неверную подпись и повтор `event_id`; не запускать реальные рассылки/звонки.
6. Отдельное подтверждение пользователя перед production, изменением обработчиков сайта и активацией workflow. Нужен план возврата к прежнему обработчику без удаления принятых заявок.
