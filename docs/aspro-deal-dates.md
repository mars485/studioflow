# Сроки сделки

Источник: тестовый портал `https://7e96.aspro.cloud/`, карточка сделки `/_module/crm/view/lead/10?tab=lead_info`. Пассивный снимок REA `ev_6b425240cf959e4eaa21dd519e3d6424dfe752bcc24748fbe01eeb8603a9df8f`, 23.10.2026. В карточке виден раздел «Сроки сделки» с датами начала и окончания; обе даты также показаны на карточке Kanban.

Сценарий StudioFlow: менеджер задаёт необязательные календарные даты начала и окончания при создании или редактировании сделки. Сервер отклоняет окончание раньше начала с 422. Даты хранятся как `date`, без преобразования часового пояса; существующие сделки получают `NULL`. Карточка показывает сохранённые даты, после перезагрузки они читаются из БД. Все запросы сделки остаются ограничены workspace и требуют существующей сессии.

Проверки: миграция `0008` на чистой изолированной PostgreSQL и `alembic check`; backend тесты в `test_crm.py` проверяют создание, изменение, ошибку диапазона и чужой workspace; React тест формы и карточки; браузерный E2E проверяет даты после перезагрузки.

Это покрывает только сроки сделки. Задачи, события и напоминания по сделке будут отдельными сценариями.
