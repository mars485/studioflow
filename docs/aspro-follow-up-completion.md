# Завершение следующего контакта по сделке

## Источник и граница исследования

Официальная справка Аспро.Cloud описывает задачи и события, связанные со сделкой, и закрытие задачи из виджета «Мои дела»: [связи со сделкой](https://aspro.cloud/help/articles/3301-3302-7340--svyazi-so-sdelkoj/), [виджет «Мои дела»](https://aspro.cloud/help/articles/3301-6977-7377--vidzhet-moi-dela/). Конкретная форма завершения из авторизованного UI портала `7e96.aspro.cloud` пока не проверена. Сценарий StudioFlow ниже — собственная реализация требования Follow-up v2 из `docs/REFERENCES.md`.

## Сценарий и данные

Менеджер открывает сделку, видит текущее следующее действие, вводит итог контакта и нажимает «Отметить follow-up выполненным». Сервер сохраняет исходный срок, тип действия и плановый комментарий в `follow_up_completions`, фиксирует имя, ID пользователя и фактическое время завершения, затем очищает текущее действие одной транзакцией. История остаётся доступной в карточке. Ошибка сохранения сохраняет введённый итог. Повторное завершение без нового действия возвращает 409. Удаление follow-up означает отмену и не создаёт запись о выполнении.

## API и права

- `GET /api/v1/workspaces/{workspace_id}/deals/{deal_id}/follow-up/completions?limit=100&offset=0` — история, новые записи первыми.
- `POST /api/v1/workspaces/{workspace_id}/deals/{deal_id}/follow-up/complete` с `{"outcome_comment": "..."}` — завершение, результат `{completion, deal}`.
- Оба маршрута требуют сессию и membership. Все запросы ограничены `workspace_id` и ID сделки; чужая сделка возвращает 404. Завершение доступно OWNER, ADMIN и MANAGER.

## Критерии приёмки

1. На чистой PostgreSQL миграция `0006` проходит без расхождения со схемой моделей.
2. Завершённое действие сохраняет срок, тип, комментарии, автора и время; после перезагрузки видно в истории.
3. Текущий follow-up очищен, повторное завершение возвращает 409 и не создаёт дубль.
4. Чужой workspace не раскрывает историю и не позволяет завершить действие.
5. При ошибке API итог остаётся в форме; браузерный E2E проверяет сохранность после перезагрузки.

Проверено изолированно 23.10.2026: backend 27/27, frontend 17/17, браузерный E2E 1/1. Сценарий Аспро.Cloud отмечен как документированный, но не проверенный в UI.
