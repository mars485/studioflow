# Интеграционные токены и входящие заявки

P2, TESTED в описанном объёме. Основа — требование `docs/REFERENCES.md`: API-токены, входящие заявки ITG и n8n. Это собственный серверный API StudioFlow, не заявка на совместимость с закрытым API Аспро.

- OWNER/ADMIN создаёт ограниченный токен `leads:create`, привязанный к одной студии и воронке. Секрет показывается только один раз; в БД SHA-256, срок, имя, безопасная подсказка и отзыв.
- Сервер сайта/n8n вызывает `POST /api/v1/integrations/leads` с Bearer и `X-StudioFlow-Request: 1`, без браузерного CORS. Токен нельзя размещать в публичном JS, формах или URL. HTTPS обязателен вне localhost.
- Проверяются срок/отзыв, активность автора и его текущая роль OWNER/ADMIN; удаление membership удаляет его токены, история принятых заявок остаётся. Токен не даёт чтения CRM или произвольного выбора workspace/воронки.
- Заявка создаёт новую компанию, при заданном имени — контакт, сделку в первом открытом этапе настроенной активной воронки и запись истории, одной транзакцией. Не выполняется автоматическое объединение компаний по совпадению имени/email.
- UUID `request_key` уникален для студии. Повтор того же нормализованного тела возвращает те же ID без копий, другой payload с тем же ключом — 409. После удаления сделки повтор не восстанавливает её, возвращает сохранённый факт с `deal_id: null`.
- Бинарное тело JSON ограничено 64 KiB по реально прочитанным байтам. По умолчанию 100 принятых уникальных заявок в час на токен; квота и идемпотентность сериализованы по workspace. На публичном reverse proxy нужны дополнительные rate/body/time limits, включая неуспешные запросы.
- Раздел «Интеграции»: управление токенами и журнал принятых заявок, OWNER/ADMIN; серверные секреты не сохраняются в localStorage. Адресов внешних сервисов и исходящих отправок нет.

Приёмка: создать токен → принять заявку → повторить без дубля → увидеть сделку; неверный/просроченный/отозванный токен не работает; чужой workspace и MANAGER не управляют токенами; квота/предел тела соблюдены; ошибка не оставляет половину клиента/сделки; сервер сайта и n8n подключаются отдельно, их адреса/ключи не предполагаются.
