# Реальные вложения сделки

Приоритет P1. Статус TESTED в описанном объёме. Основа исследования: блок файлов в карточке сделки, см. [карточку v2](deal-card-v2.md). Собственная реализация StudioFlow, без копирования хранилища референса.

## Объём и правила

- Загрузка бинарного содержимого, автор/дата/имя/реальный размер/SHA-256, скачивание и удаление.
- Старые записи с одними метаданными сохраняются и явно обозначаются как недоступные для скачивания.
- Для небольших файлов MVP содержимое хранится в отдельной таблице PostgreSQL BYTEA: атомарность с метаданными, общая резервная копия и каскадное удаление, без публичных URL и файловых путей.
- Лимит по умолчанию: 10 MiB на файл и 100 MiB содержимого на workspace; настраиваемые ограниченные параметры окружения. Квота проверяется под блокировкой workspace.
- Raw binary upload вместо multipart; ограничение фактически прочитанных байтов независимо от Content-Length. Авторизация проверяется до чтения тела. Для публичной установки дополнительно нужен лимит тела/таймаут на reverse proxy и антивирусная проверка.
- UUID запроса делает повтор после сетевой ошибки идемпотентным; тот же ключ с другим содержимым/именем — 409.
- Каждый маршрут проверяет workspace и сделку. Все участники с доступом к сделке могут загружать/скачивать/удалять (текущее правило карточки). После отзыва membership доступ прекращается.
- Скачивание только `attachment`, `application/octet-stream`, `nosniff`; HTML/SVG не исполняются на домене приложения. Имена без путей/управляющих символов; никакой записи по пользовательскому пути.

## Приёмка

Файл после reload скачивается побайтно; чужой workspace и сделка недоступны; превышение лимита/квоты отклоняется; повтор не создаёт копию; удаление вложения/сделки удаляет содержимое; ошибка оставляет выбранный файл для повтора. Миграция сохраняет старые метаданные.

Не входит: большие файлы, S3, публичные ссылки, предпросмотр и антивирус. Это не означает, что загруженный файл безопасен: проверяйте его перед открытием.

## Реализация и проверки 24.10.2026

- `0016_attachment_contents`, `attachments.py`; `POST /deals/{id}/attachments/upload?filename=...&upload_key=<UUID>` с бинарным телом; `GET /deals/{id}/attachments/{id}/download`.
- Старый POST метаданных оставлен для совместимости, но UI использует настоящую загрузку. В ответе `has_content`, `sha256` отличают реальный файл от старой записи.
- `ATTACHMENT_MAX_BYTES` (1–25 MiB), `ATTACHMENT_WORKSPACE_QUOTA_BYTES` (1 byte–1 GiB); defaults 10/100 MiB. Резервное копирование БД включает байты. Downgrade до `0015` сохраняет метаданные, но **удаляет бинарное содержимое** — только после резервной копии.
- `test_attachments.py`: побайтное скачивание, старые записи, каскад, квоты/stream без Content-Length, повтор ключа, CSRF, workspace/deal isolation, отзыв membership, имена, пустой файл и безопасные заголовки HTML.
- `DealDetails.test.tsx`: бинарное тело, ссылка скачивания, сохранение выбранного файла и ключа при ошибке/повторе.
- `e2e/attachments.spec.ts`: реальная загрузка → reload → скачивание и сравнение байтов → удаление. Срез вложений: backend 61/61, frontend 40/40 + build, E2E 4/4.
- Локальная dev-база обновлена до `0016` после `pg_dump`; production не затрагивался.
