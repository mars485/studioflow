# Аудит основных изменений сделок

P3, TESTED в описанном объёме. `docs/REFERENCES.md` требует аудит действий. Официальная [справка о записи в историю](https://aspro.cloud/help/articles/3301-3300-3321--avtodejstvie-zapis-v-istoriyu) подтверждена поисковой выдержкой 24.10.2026: лента сделки содержит историю изменений. Полный административный аудит референса не исследован. Ниже отдельный собственный сценарий, не полная история всех действий системы.

- После установки `0025` сохраняются создание, изменение через основной PATCH и удаление сделки, включая создание через входящий токен. Старые действия не реконструируются.
- Запись и CRM-операция атомарны: при rollback не остаётся записи; повтор PATCH без фактического изменения не создаёт событие. Повтор входящей заявки не создаёт вторую запись.
- Журнал содержит workspace, UUID сделки, время сервера, тип операции, UUID/имя автора либо UUID интеграционного токена и список имён изменённых полей. Значения полей, название сделки, описания, телефоны, email, содержимое файлов и секреты не копируются.
- Журнал переживает удаление сделки и отзыв membership автора. Нет API редактирования/удаления записей; это не защита от администратора БД, не криптографический и не юридический аудит. Удаление workspace или downgrade удаляет журнал.
- Читают только OWNER/ADMIN своей студии, страницы по 50, фильтр по UUID сделки/операции. UI показывает автора, время, поля и UUID; удалённая сделка не открывается как новая форма.
- На этом срезе не журналируются чтения/неудачные запросы, входы, отдельные follow-up endpoints, комментарии/поля/связи из дополнительных API, компании/контакты, задачи, проекты, финансы и изменения прав. Лента сделки остаётся прежней; аудит не выдаётся за её замену.

Приёмка: создать → PATCH → повтор PATCH → удалить → прочитать три записи после reload; одинаковые данные запроса не копируются в журнал; MANAGER/чужая студия не читают; rollback и повтор входящей заявки не оставляют дублей; миграция не переписывает сделки.
