## Наблюдаемое поведение

Список проектов: вкладки Активные / Гант / В архиве / Все, поиск, настройки колонок, экспорт, выбор рабочего процесса. Колонки: Проект, Этап, Начало, До дедлайна, Поступления (план/факт), Списания (план/факт), Баланс (план/факт), Выручка (факт), Расходы (факт), Прибыль (факт), Менеджер, Ассистент менеджера, Теги.

Карточка проекта: вкладки Общие, Задачи, Гант, Порядок работ, Документы, Финансы, Команда, События; действия «Завершить», «Создать», «Документ». На доске задач проект виден как связь «Проект: <название>» с прогрессом.

## Что уже есть в StudioFlow

Ничего: экран «Проекты» демонстрационный, моделей и API нет. Задачи существуют только в сделке.

## Объём первой итерации (P2)

1. Проект как сущность workspace: название, клиент, сделка-источник, менеджер, этап, даты, статус (активный/архив/завершён).
2. Создание проекта из выигранной сделки одной операцией с переносом клиента, контактов и суммы.
3. Список проектов с вкладками Активные / Архив / Все и базовыми колонками без финансового блока.
4. Карточка проекта: вкладки Общие, Задачи, Команда, События.
5. Связь задачи с проектом (из модуля задач) и отображение прогресса по задачам.

Не входит: «Порядок работ» (требует отдельной модели этапов работ), Гант, экспорт, финансовые колонки и вкладка «Финансы», документы, шаблоны проектов, ассистент менеджера, управление этапами проектов из интерфейса.

## Модель данных и миграция

Реализовано миграцией `0013_project_module`:

- `project_stages` (`workspace_id`, `name`, `position`) с этапами по умолчанию: «Подготовка», «В работе», «Сдача», «Завершён»;
- `projects` (`workspace_id`, `title`, `client_id`, `deal_id`, `manager_user_id`, `stage_id`, `amount`, `currency`, `start_date`, `end_date`, `status`, `archived_at`);
- `project_members` (`workspace_id`, `project_id`, `user_id`, `role` `LEAD | MEMBER`);
- `project_contacts` — перенесённые из сделки контакты;
- `project_events` — журнал создания, смены статуса, изменений команды и заметок;
- `tasks.project_id` со связью `SET NULL`: удаление проекта не удаляет задачи;
- `projects.deal_id` и `tasks.contact_id` переведены на одноколоночные `SET NULL`, потому что составной внешний ключ обнулял бы и `workspace_id`.

## Критерии приёмки

1. Проект создаётся из сделки: клиент, контакты и сумма переносятся, сделка остаётся доступной и не дублируется.
2. Повторное создание проекта из той же сделки без `force: true` возвращает 409; с явным подтверждением создаётся второй проект.
3. Архивный проект недоступен для новых задач; история сохраняется.
4. Участник проекта должен быть активным участником workspace.
5. Список проектов и карточка доступны только в своём workspace.
6. Существующие сделки, задачи и контакты не меняются.

## API и UI

Backend: `backend/app/api/v1/projects.py`, все маршруты workspace scoped:

- `GET /project-stages` — этапы студии создаются при первом запросе;
- `GET /projects?status=active|archive|all` с фильтрами `client_id`, `deal_id`, прогрессом задач и числом участников;
- `POST /projects` — из выигранной сделки (иначе 422) или вручную; переносит клиента, сумму, менеджера и контакты сделки, пишет событие; повтор без `force` даёт 409;
- `GET/PATCH/DELETE /projects/{id}` — смена этапа, менеджера, дат и статуса; архивный проект не принимает новые задачи; удаление только для владельца и администратора;
- `GET/POST/DELETE /projects/{id}/members`, `GET /projects/{id}/contacts`, `GET/POST /projects/{id}/events`;
- `tasks.project_id` участвует в `GET/POST/PATCH /tasks` и блокируется для архивных проектов.

Frontend: `frontend/src/Projects.tsx` (пункт меню «Проекты») — список с вкладками, создание из сделки или вручную, карточка с вкладками Общие, Задачи, Команда, События, архивирование и возврат.
