# Повторение задачи после завершения

P2, TESTED в описанном объёме. [Справка Аспро о регулярных задачах](https://aspro.cloud/help/articles/3281-6630--regulyarnye-zadachi) и [режимах/интервалах](https://aspro.cloud/help/articles/3281-6630-6631--rezhimy-i-intervaly-regulyarnyh-zadach) подтверждает наличие повторений; конкретные внутренние правила не проверены. Ниже собственный ограниченный сценарий StudioFlow, не календарный планировщик Аспро.

- У незавершённой задачи можно включить повтор через 1–365 суток после завершения, ограниченный 1–365 следующими задачами.
- Только переход из открытого в завершающий статус создаёт одну следующую задачу в той же транзакции. Работает через общий и совместимый API сделок. Повторный запрос и повторное завершение переоткрытой задачи не создают второго продолжения.
- Переносятся название, описание, приоритет, оценка, активный исполнитель, существующие связи со сделкой/контактом/проектом, пункты чек-листа (сброшены). Подзадачи, наблюдатели, напоминания и трудозатраты не копируются. Постановщик — завершивший пользователь.
- Следующая задача начинается через заданное число 24-часовых суток от серверного времени завершения. Если у исходной был срок, сохраняется длительность между началом и сроком; без начала срок считается от завершения. Время хранится UTC, локальный час при переходе DST может измениться — это явно не повтор «каждое утро в 9».
- Повторение для подзадачи запрещено. Если связанный проект архивный, завершение задачи сохраняется, но следующая задача не создаётся; в правиле видна причина остановки. Удалённый участник не назначается. Можно отключить правило, история созданного продолжения остаётся.
- Настраивать могут участники студии с обычным доступом к задаче. Ограничение всего сценария текущими OWNER/ADMIN/MANAGER сохраняется; отдельного планировщика, фоновой генерации, бесконечных циклов и внешних отправок нет.

Приёмка: настроить повтор → завершить → увидеть новую задачу/сброшенный чек-лист/сроки после reload; повторное завершение не создаёт дубль; лимит цепочки соблюдён, отключённое правило не создаёт задач, чужой workspace недоступен; конкурентные завершения создают одно продолжение.

Проверено 24.10.2026: backend 84/84, frontend 62/62 + build, E2E 8/8. `test_task_recurrence.py`: цепочка/границы/сроки/чек-листы, оба API, выключение и архив проекта; `test_task_time_concurrency.py`: пять независимых завершений создают одного продолжателя, одновременно закрывается таймер. `TaskRecurrence.test.tsx` и расширенный `e2e/task-time.spec.ts`: настройки и переход к созданному продолжению после reload. `0023` применена к dev после `pg_dump`; downgrade удаляет правила повторения, не созданные задачи.
