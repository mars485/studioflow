# Общий поиск студии

P3, TESTED в описанном объёме. Глобальный поиск наблюдался в шапке референса (`feature-inventory.md`), подробный алгоритм ранжирования не подтверждён. Самостоятельный сценарий StudioFlow:

- Поиск в выбранной доступной студии по сделкам, компаниям, контактам, задачам и проектам. Минимум 2, максимум 255 символов, явная отправка формы и фильтр типа. Подстрока без регистра, символы `%`, `_` и `\` трактуются буквально.
- Сделки: название/источник/контактное имя; компании/контакты: имя, телефон, email; задачи: название и описание; проекты: название. Файлы, финансовые документы, пароли, токены, private inbox и тексты переписки не индексируются.
- SQL UNION с workspace scope в каждой ветке, страницы по 50 результатов, стабильный порядок тип/название/ID. Возвращаются тип, ID, заголовок и состояние, не полное содержимое описания.
- Переход открывает точный объект в нужной студии, включая подзадачу/архивный проект. Исчезнувший объект явно недоступен, вместо создания пустой новой карточки.
- Пустые результаты, ошибки/повтор и сохранение поискового запроса. Пока без морфологии, полнотекстового индекса, опечаток и межпространственного поиска.

Приёмка: один запрос находит связанные объекты разных типов; чужой workspace не даёт результат; спецсимволы буквальны; пагинация стабильна; переход открывает исходный ID/студию после reload данных.
