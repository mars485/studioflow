# Порядок работ и временная шкала проекта

P2, TESTED в описанном объёме. В карточке референса наблюдались отдельные вкладки «Порядок работ» и «Гант»; см. [проектный сценарий](projects-module.md). Реализованный ниже упрощённый план — собственный сценарий, не полное повторение Ганта Аспро.

- У проекта — упорядоченные этапы исполнения, отдельные от стадии карточки проекта. Название, ответственный из участников студии, даты начала/окончания, состояние «Запланировано / В работе / Готово».
- CRUD и порядок в workspace scoped API, блокировка проекта на время изменений, максимум 500 этапов. В архивном проекте план доступен только для чтения.
- Все участники могут создавать/редактировать/переставлять, удаление только OWNER/ADMIN. Даты согласованы, null для обязательных полей запрещён. Пользователь не может назначить участника другой студии.
- UI: «Порядок работ», редактирование и сохранение формы с ошибками; отдельная временная шкала «Гант» для этапов с датами, недатированные — отдельным списком. Полосы информационные, изменение дат в форме плана.
- Изменения записываются в события проекта. Отзыв membership снимает активное назначение; сам план не удаляется.
- Нет зависимостей, критического пути, автопланирования, ресурсных ограничений и drag-and-drop дат. Задачи пока связаны с проектом в целом, не с этапом плана. Шаблоны — следующий отдельный сценарий.

Приёмка: создать два этапа, назначить, сохранить даты, изменить порядок и статус, reload; временная шкала соответствует датам, архив запрещает запись; чужие workspace/проекты недоступны; удаление проекта каскадно удаляет его этапы.

Реализация `0019_project_work_plan`, `project_work.py`, `ProjectWorkPlan.tsx`.
