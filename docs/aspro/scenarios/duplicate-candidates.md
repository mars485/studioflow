# Контроль возможных дублей клиентов

P1, TESTED только выявление кандидатов. Поисковая выдержка официальной [справки о контроле дубликатов](https://aspro.cloud/help/articles/3301-3304-3356--kontrol-dublikatov), 24.10.2026, подтверждает ручной выбор записей и целевой записи для объединения. Этот срез StudioFlow реализует только безопасное выявление кандидатов, без объединения/удаления и без заявления полной совместимости.

- В разделе «Клиенты» у компании/контакта можно явно запросить возможные дубли того же типа в той же студии. Доступ совпадает с чтением каталога, включая MANAGER.
- Причины: точный email без регистра/краевых пробелов; телефон после удаления недесятичных ASCII-символов (не менее 7 цифр); полное имя без регистра с нормализацией пробелов (не менее 3 символов). Пустые поля не совпадают. Код страны, 8/7, добавочные номера и опечатки не нормализуются; совпадение имени не доказывает дубль.
- Текущий объект исключён. Серверная пагинация по 50, стабильный порядок название/UUID, явное общее количество и причины для каждого кандидата. Можно открыть точную карточку для сравнения. Для изменения данных используются прежние формы и права.
- Нет фонового поиска, автоматического объединения, изменения связей, счетов, истории и существующих данных. Слияние с выбором основной записи — отдельный ещё не реализованный сценарий: необходимы перенос всех ссылок и защита финансовых снимков.

Приёмка: форматированные телефоны/email/имена дают кандидатов с причинами; пустые поля и короткие имена не дают массовых совпадений; чужой workspace не раскрывается; открывается исходная карточка кандидата, ошибки повторяемы; сам поиск ничего не меняет.

Реализация: `api/v1/duplicates.py`, `DuplicateCandidates.tsx` и кнопки каталога Clients. Перед открытием кандидат повторно читается по точному UUID: новая запись включается в каталог, удалённая возвращает ошибку, а не пустую форму создания. Новых таблиц и миграций нет. Проверено 24.10.2026: backend 103/103 с `alembic check`, frontend 79/79 + build, E2E 11/11. `test_duplicates.py`: компании/контакты, нормализация/причины, страницы, пустые поля, роли/изоляция. `DuplicateCandidates.test.tsx`: сравнение, повтор ошибки, удалённый кандидат. `e2e/duplicates.spec.ts`: проверка причин → точная карточка → reload → обе компании остаются раздельными.

## Дополнение 26.10.2026

Проверка кандидатов остаётся read-only. OWNER/ADMIN может отдельно открыть предпросмотр явного слияния [компаний](company-merge.md) или [контактов](contact-merge.md); сама проверка ничего не изменяет. Объединение происходит только после отдельного подтверждения.
