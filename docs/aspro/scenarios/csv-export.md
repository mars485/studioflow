# CSV-экспорт CRM

P3, TESTED в описанном объёме. Экспорт таблиц наблюдался при исследовании списков референса (`feature-inventory.md`); точный формат Аспро не воспроизводится. Собственный CSV StudioFlow:

- Только OWNER/ADMIN, отдельный workspace-scoped GET, выгрузка сделок выбранной воронки либо компаний/контактов студии. Текущий текстовый поиск UI не применяется, это явно подписано.
- UTF-8 BOM, разделитель `;`, кавычки CSV; отдельные валюты, UUID и даты ISO. Текст не интерпретируется как HTML или формула: опасные префиксы `= + - @` после пробелов/BOM экранируются апострофом, начальные табуляции/переносы также.
- Максимум 5000 строк; при превышении ошибка 413, а не молчаливо обрезанный файл. Это не полный backup (нет файлов, паролей, токенов и истории).
- Ошибка скачивания показывается в UI, повтор доступен. Файлы создаются только по явному действию пользователя в браузере, нет отправки в сторонний сервис.

Приёмка: Unicode/кавычки/точка с запятой корректно читаются стандартным CSV-парсером; формулы экранированы; чужой workspace и MANAGER не получают выгрузку; скачанный браузером CSV содержит сохранённую сделку, не чужие данные.

Проверено 24.10.2026: backend 95/95, frontend 68/68 + build, E2E 8/8. `test_exports.py`: CSV-парсер, формулы, роли/workspace, отказ при 5001 строке; `CsvExport.test.tsx`: ошибка/повтор и успешное скачивание. `e2e/integrations.spec.ts`: CSV содержит созданную через API сделку. `e2e/crm.spec.ts` проверяет DnD реальной карточки на видимый заголовок стадии и отсутствие горизонтального переполнения страницы; `Layout.css` удерживает широкую доску внутри своей области прокрутки. Сборка и общий E2E повторены после исправления компоновки. Новых таблиц/миграций нет.
