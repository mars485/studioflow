# Единый основной контакт сделки

P1, TESTED в описанном объёме. Уточнение наблюдаемого списка контактов карточки: основной контакт должен совпадать в форме сделки, списке связей и создаваемом проекте.

- Если связи есть, одна из них основная, `Deal.contact_id` указывает на неё. Первый добавленный контакт автоматически основной.
- Выбор основного через любой API синхронизирует обе формы. Старый основной остаётся дополнительным контактом при смене.
- Удаление основной связи назначает старейшую оставшуюся; удаление последней очищает основной контакт. Сам контакт/компания не удаляются.
- Очистка поля основного контакта в старой форме отвязывает его от сделки; при наличии других выбирается старейший. Снять основной признак с единственного контакта без удаления нельзя.
- Дополнительные контакты могут быть из другой компании того же workspace (наблюдаемое поведение). Старый API по-прежнему требует контакт компании, либо уже явно связанную со сделкой запись.
- Все изменения сериализованы блокировкой строки сделки. UI перечитывает канонический объект после операций связей.

## Сохранность и миграция

`0018` добавляет отсутствующую связь для старого `Deal.contact_id`, не удаляя существующих. При конфликте ранее явно выбранная основная связь имеет приоритет; прежний контакт остаётся дополнительным. Если явного основного нет — выбирается прежний `contact_id`, затем старейшая связь. Имя основного синхронизируется, другие контактные данные не меняются. Обратный переход не восстанавливает прежнюю несогласованность и не удаляет добавленные связи.

Приёмка: создание старым API → видимость в списке; смена основного с двух сторон → одна основная связь; удаление/очистка → корректная замена; контакты сохраняются; чужие workspace недоступны; заполненная миграция сохраняет оба конфликтующих контакта.
