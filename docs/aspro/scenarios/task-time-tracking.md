# Учёт времени задач

P2, TESTED в описанном объёме. Официальная справка подтверждает [таймер учёта времени в задаче](https://aspro.cloud/help/articles/3281-6629--uchet-vremeni-v-zadachah); доступны поисковые выдержки. Ниже — самостоятельные правила StudioFlow, без предположений об автоматических переходах статусов Аспро.

- Ручная запись: дата работы в часовом поясе студии, минуты, комментарий, автор. Таймер: серверные начало/остановка и фактические целые секунды. Один активный таймер на пользователя в workspace.
- UUID операции для создания ручной записи/старта делает сетевой повтор идемпотентным. Остановка по ID также идемпотентна. Новый старт не продолжает старую закрытую запись.
- Все участники видят журнал задачи. Создают только свои записи, меняют/удаляют свои; OWNER/ADMIN также могут управлять чужими. Таймерные даты и длительность не переписываются вручную. Активную запись сначала останавливают.
- Закрытие задачи останавливает её таймеры. Отзыв membership останавливает таймеры участника, сохраняет историю и имя автора; доступ отзывается. Запуск таймера не меняет статус задачи и запрещён для завершённой задачи.
- Ручные минуты положительные, максимум 525600 на запись; будущие даты относительно timezone студии не принимаются. Таймер через полночь относится к дате старта, не разбивается по дням автоматически.
- Журнал с пагинацией и суммой закрытых записей; бегущий таймер показан отдельно и сохраняется после reload. Это не табель, не зарплатный/бухгалтерский расчёт и не выставление счёта клиенту.

Приёмка: ручная запись и таймер сохраняются после reload; повтор не удваивает часы; конкурентные старты не запускают два таймера; другой пользователь не меняет чужую запись; чужой workspace недоступен; завершение задачи/отзыв membership останавливают таймер без удаления истории.

Реализация: `0022_task_time`, `api/v1/task_time.py`, `services/task_time.py`, `TaskTime.tsx`. Workspace → task → запись времени — единый порядок блокировок; частичный уникальный индекс дополнительно запрещает два активных таймера. В журнале сумма закрытых записей, текущий личный таймер отдельно, обновление с сервера явной кнопкой. Отображаемое тиканье не является источником сохраняемой длительности.

Проверено 24.10.2026: backend 81/81, frontend 60/60 и build, E2E 8/8. `test_task_time.py`: валидация/повтор, ручное редактирование, права, оба API завершения и отзыв membership. `test_task_time_concurrency.py`: независимые транзакции старта и повторов на одноразовой БД. `TaskTime.test.tsx`: ошибочный черновик и ключ операции, восстановление таймера; `e2e/task-time.spec.ts`: ручное время → таймер → reload → завершение → reload. Миграция применена к dev после резервной копии `studioflow-before-0022-20261024.dump`. Downgrade удаляет журнал времени, но сохраняет задачи.

Граница идемпотентности: ключ сравнивается с текущим содержимым записи. После ручного редактирования старый create-запрос может вернуть 409, после удаления записи её ключ освобождается. UI не повторяет успешно подтверждённое создание и сохраняет тот же ключ только для сетевого повтора неизменённого черновика.
