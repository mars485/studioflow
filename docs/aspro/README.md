# Каталог Аспро.Cloud для StudioFlow

Этот каталог хранит исследование референса Аспро.Cloud и производные сценарии.

## Структура

| Файл | Роль |
| --- | --- |
| `feature-inventory.md` | Каталог наблюдаемых функций и разделов, Evidence и решение по приоритету |
| `scenarios/*.md` | Сценарии, которые ещё не реализованы: что наблюдалось, что делаем, критерии приёмки |
| `../aspro-parity-matrix.md` | Матрица статусов реализации — единственный источник истины по «сделано/протестировано» |
| `../aspro-*.md` | Прежние сценарии, оформленные до появления каталога (оставлены на месте, ссылки из матрицы сохраняются) |

## Правила

1. Наблюдение фиксируется с идентификатором Evidence и датой; без Evidence пункт попадает в раздел «не проверено».
2. Сценарий описывает поведение и данные, а не копию интерфейса: тексты, вёрстка, иконки и код Аспро.Cloud не переносятся.
3. Один сценарий — один PR: миграция, workspace scoped API, авторизация, UI с обработкой ошибок, тесты.
4. После реализации обновляются сценарий, `feature-inventory.md` и строка в `aspro-parity-matrix.md`.
5. Демоданные и персональные данные тенанта не попадают в репозиторий.

## Старый и новый формат

Прежние сценарии лежат плоско: `docs/aspro-company-profile.md`, `aspro-contacts.md`, `aspro-deal-dates.md`, `aspro-deal-responsible.md`, `aspro-deal-tasks.md`, `aspro-follow-up-completion.md`, `aspro-my-day.md`, `aspro-pipeline-lifecycle.md`, `aspro-pipeline-stages.md`, `aspro-task-reminders.md`, `aspro-task-research.md`. Переносить их не обязательно: новые сценарии оформляются в `scenarios/`, старые остаются действительными и на них ссылается матрица.
