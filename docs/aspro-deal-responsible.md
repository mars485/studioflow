Источник: поле «Ответственный» наблюдалось REA в доступной форме сделки на `https://7e96.aspro.cloud/` 23.10.2026 (evidence `ev_59f40494c9bba1dcb27ea621c3f02f25430572bb7594cda01b8156d9849e6145`). Состав вариантов и права в Aspro.Cloud не исследованы; StudioFlow использует участников собственного workspace.

## Сценарий

В форме создания и редактирования сделки пользователь выбирает ответственного из участников студии либо оставляет «Не назначен». В карточке и на доске показывается имя. API принимает `responsible_user_id` как UUID или `null` и проверяет активное членство в том же workspace; чужой или неактивный пользователь даёт 422. При удалении участника его назначения в сделках студии снимаются в той же транзакции. Существующие сделки без ответственного остаются допустимыми; миграция не нужна, поскольку колонка уже существует в исходной схеме.

## Критерии приёмки

1. Создание, изменение и очистка назначения сохраняются после перезагрузки.
2. В назначении нельзя указать пользователя без членства в текущей студии.
3. Удаление участника снимает его назначения.
4. Права и изоляция workspace сохраняются; ошибка API видна в форме без потери ввода.
