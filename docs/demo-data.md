# Локальные демоданные

Только для наглядного просмотра StudioFlow. Это вымышленные клиенты, контакты, сделки, задачи, проекты и учебные финансовые записи. Их нельзя использовать как настоящие реквизиты, документы или поступления.

## Запуск

Сначала проверить изолированные тесты и убедиться, что `127.0.0.1:8000` — локальный dev API из `docker-compose.yml`, не туннель в production. Сделать резервную копию локальной БД. Не запускать против рабочего сервера.

```powershell
python backend/app/seed_demo.py --base-url http://127.0.0.1:8000 --credentials-file "C:\Users\ainur\AppData\Local\Temp\opencode\studioflow-demo-credentials.json" --confirm-local-demo
```

- Отдельный аккаунт `demo@studioflow.example.com` со случайным паролем; пароль сохраняется только в указанном приватном JSON вне репозитория. Сохраните файл для повторного запуска, не отправляйте его в Git/публичные логи. На Windows доступ к файлу определяется ACL родительской папки.
- Отдельное пространство `IT GROUP · Демо (учебные данные)`. Существующие пользователи не получают новых прав. Для просмотра выйти из текущего аккаунта и войти под демо-аккаунтом; данные текущей студии не меняются.
- Только стандартный API с сессией, CSRF-заголовком и проверками прав. Нет SQL-обхода авторизации, миграций, автозапуска seed при старте и реальных внешних отправок. Финансовые записи — только локальные учётные отметки.
- При повторном запуске IDs из файла позволяют читать уже созданные записи, не дублируя и не перезаписывая пользовательские правки. Удалённые записи автоматически не восстанавливаются; неизвестное существующее пространство не присваивается.
- Частичный сбой не откатывает предыдущие API-вызовы. Исправить причину и повторить с тем же файлом. Если сбой произошёл между созданием объекта и сохранением его ID, скрипт останавливается на совпадении имени вместо дублирования. Завершённые пользователем follow-up/задачи не сбрасываются.
- Только loopback HTTP, без redirects. Это дополнительный предохранитель, не способ определить назначение локального туннеля.

## Набор

5 компаний, 5 контактов, 12 сделок по четырём стадиям, прошлые/сегодняшние/будущие follow-up, заметки и адресное демо-упоминание; 3 проекта из выигранных сделок, 9 задач с разными статусами/приоритетами/сроками; учебная организация, 4 счёта: черновик, выставлен, частично оплачен и оплачен. Даты задаются относительно первого запуска; повторный запуск не двигает сроки.

Сначала набор проверяется на disposable API/БД, включая повторный запуск и счётчики из API. Рабочие/production данные не используются в проверках.
